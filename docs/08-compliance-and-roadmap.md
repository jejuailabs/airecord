## 1. 세션 로그 — 기능이 아니라 부산물

`core.md §3-5`에 따라, 녹음 모듈을 따로 만들지 않는다. 파이프라인에 이미 흐르는 데이터에 저장 단계 하나를 붙일 뿐이다.

```
번역 엔진 출력 ─┬─→ 자막 렌더 (즉시, 지연 민감)
                └─→ 세션 로그 (배치, 지연 무관)
                      ├─ 원문 전사 + 타임스탬프
                      ├─ 번역문 + 타임스탬프
                      └─ 오디오 (storeAudio === true 일 때만)
```

**저장 규칙**
- 확정 세그먼트만 저장한다. 부분 전사는 저장하지 않는다(`docs/03 §3`).
- 배치 단위: 10건 또는 5초 중 먼저 도달하는 쪽.
- **저장 실패가 통역을 멈추지 않는다.** 로컬 버퍼에 쌓고 재시도, 최종 실패 시 세션에 `logIncomplete: true` 플래그만 남긴다.
- 오디오 저장은 **기본 꺼짐**. 워크스페이스 설정에서 명시적으로 켜야 한다. 켜져 있으면 자막 화면 상단에 항상 표시한다.

**내보내기**
| 형식 | 내용 |
|---|---|
| TXT | 시각 + 원문 + 번역 |
| Markdown | 위 + 메타데이터 헤더 |
| PDF | 표지(제목·일시·언어·참여자) + 2열 대조표 |
| 오디오 | 저장 설정이 켜진 세션만 |

내보내기는 Vercel 함수에서 동기로 만들지 않는다. 요청 → 생성 큐 → Storage 업로드 → 완료 알림 순으로 비동기 처리한다(긴 세션은 30초를 넘긴다).

## 2. 고지 및 동의

### 2.1 왜 필요한가
국내 통신비밀보호법상 **대화 당사자 본인이 자신이 참여한 대화를 녹음하는 것은 원칙적으로 문제되지 않으나, 대화에 참여하지 않은 제3자가 타인 간 대화를 몰래 녹음·청취하는 것은 금지**된다. 우리 서비스는 구조적으로 **봇이 대화에 들어가 오디오를 처리**하므로, "당사자 녹음"인지 "제3자 녹음"인지가 상황에 따라 달라질 수 있는 회색지대가 존재한다.

또한 대화 내용에는 개인정보가 포함되며, 이를 저장·처리하려면 별도 근거가 필요하다. **고지는 이 리스크를 낮추는 가장 값싼 수단**이다.

> ⚠ 위 법리 요약은 일반론이며, 구체적 사안 판단은 다르다. 출시 전 변호사 검토 필수.

### 2.2 어디에 무엇을 띄우나

| 위치 | 문구 | 방식 |
|---|---|---|
| 모드 B 시작 버튼 위 | "이 대화는 통역과 기록을 위해 처리됩니다." | 항상 표시 (동의 클릭 불필요, 시작이 곧 동의) |
| 봇 입장 시 회의 채팅 | "🌐 실시간 통역 자막: {링크} · 이 회의는 통역을 위해 처리됩니다." | 자동 게시 |
| 자막 뷰어 첫 진입 | 하단 배너 1회 | 닫기 가능, 세션당 1회 |
| 봇 표시 이름 | "<브랜드> 통역" | 참가자 목록에서 봇의 존재가 드러나야 한다 |
| 오디오 저장 켜진 세션 | 자막 화면 상단에 상시 표시 | 숨길 수 없음 |

**설계 원칙: 봇의 존재를 숨기지 않는다.** 참가자 목록에 뜨는 이름, 채팅에 남는 메시지, 자막 화면의 고지 — 이 세 가지로 "지금 통역 도구가 돌고 있다"는 사실이 자연스럽게 드러나게 한다.

### 2.3 해외 참가자
회의에 다른 국가 참가자가 있으면 **그 국가의 개인정보 규정도 적용될 수 있다**(EU라면 GDPR 등). 구체적 대응은 Enterprise 계약 단계에서 다루고, MVP에서는 다음만 한다.
- 데이터 저장 리전을 문서에 명시한다.
- 워크스페이스 단위로 **오디오 저장 끄기 · 보관 기간 최소화**를 선택할 수 있게 한다.
- 세션 즉시 삭제 기능을 제공한다.

## 3. 데이터 보관 및 삭제

| 데이터 | 보관 | 삭제 |
|---|---|---|
| 세그먼트(자막) | 플랜별 `retentionDays` (7 / 90 / 365) | 만료 시 배치 삭제 |
| 오디오 | 세그먼트와 동일하되, 저장 설정 켜진 경우만 | 만료 시 배치 삭제 |
| 세션 메타(시간·분·언어) | 무기한 | 과금 근거이므로 보존 |
| 사용량 집계 | 무기한 | |
| 계정 | 삭제 요청 시 30일 유예 후 하드 삭제 | |
| 개별 세션 즉시 삭제 | 유저 요청 시 즉시, 유예 없음 | 삭제 사실만 감사 로그 |

**보안 기본선**
- 전송 구간 TLS, 저장 구간 암호화(Firebase 기본).
- 자막 뷰어 토큰은 32자 랜덤, 세션 종료 + 보관 기간 후 자동 만료. 관리자가 즉시 폐기 가능.
- API 키는 서버에만. 모드 B의 임시 토큰은 **수명을 짧게, 세션 1회용으로** 발급(`docs/04 §3`).
- 접근 로그: 누가 어떤 세션 기록을 열람했는지 기록(Business 이상).

## 4. 로드맵

### Phase 1 — 대면 모드 코어
**목표: "이게 실제로 쓸 만한가"를 확인한다. 다른 건 아무것도 하지 않는다.**
- 마이크 → 번역 엔진 직결 → 자막 렌더
- 디자인 토큰·라이트/다크 (`docs/05`)
- 로그인 없음, 저장 없음, 과금 없음
- **완료 기준:** 실제 이중언어 대화 10건에서 자막만으로 대화가 진행된다. `docs/04 §6` 실측표가 채워진다.

### Phase 2 — 계정 · 워크스페이스
- Google 로그인, Firestore 스키마 전체, 세션 목록/상세, 세그먼트 저장
- next-intl ko/en
- **완료 기준:** 로그인 → 통역 → 기록 열람이 끊김 없이 된다.

### Phase 3 — 사용량 · 요금제
- 미터링(하트비트·하드 캡), 사용량 대시보드, 플랜, 결제 연동
- **선행 조건:** 가격 가설 검증 (§`docs/07 §4` — 대상 고객 10곳 이상 가격 대화)
- **완료 기준:** `docs/07 §6` 벤더 실청구 대조 괴리율 5% 이내.

### Phase 4 — 화상회의 모드
- Realtime Worker 배포, Recall.ai 어댑터, 자막 링크 자동 게시, 뷰어 화면, 폴백 활성화
- **완료 기준:** Zoom·Teams·Meet 각각에서 봇 입장 → 자막 게시 → 종료가 5회 연속 성공.

### Phase 5 — 로그 · 고지 · 다국어 완성
- 내보내기(TXT/MD/PDF), 고지 UI 전면 적용, 보관 정책 배치, ja/zh-CN 번역
- **선행 조건:** 변호사 검토 완료
- **완료 기준:** 개인정보 처리방침·이용약관 게시, 삭제 요청 흐름 동작.

### Phase 6+ — 확장 (우선순위 미정)
- 헤드셋 음성 채널 정교화 (드리프트 관리 개선)
- 다국어 동시 출력 (한 세션에서 영·일·중 자막 동시)
- Zoom 네이티브 자막창 연동 (설정 부담 vs 편의 재평가)
- 회의 요약·액션아이템 추출
- 용어집(회사 전문용어 사전) 반영
- SSO / 감사 로그 / DPA (Enterprise 요건)

## 5. 리스크 대장

| 리스크 | 성격 | 대응 |
|---|---|---|
| 벤더가 번역 API 가격을 올린다 | 사업 | 단가를 설정값으로 분리, 2개 벤더 어댑터 유지, 계약 시 가격 변동 조항 확보 |
| 벤더가 이 기능을 기본 제공한다(줌·팀즈 자체 통역) | **실존적** | 우리 차별점은 "설정 zero + 대면·화상 통합 + 기록". 플랫폼 종속 기능이 커버 못 하는 영역에 집중 |
| 번역 품질이 실무에서 부족하다 | 제품 | Phase 1에서 검증. 안 되면 여기서 멈추는 게 옳다 |
| 헤비 유저가 마진을 잠식한다 | 사업 | 무제한 금지, 포함분+종량 하이브리드 (`docs/07 §3`) |
| 녹음 관련 법적 분쟁 | 법무 | 고지 3중화, 오디오 저장 기본 꺼짐, 변호사 검토 |
| Realtime Worker 장애 = 모드 A 전면 중단 | 운영 | min-instances ≥1, 헬스체크, 모드 B는 워커와 무관하게 동작(구조적 격리) |
| 시장이 생각보다 작다 | 사업 | **현재까지 국내 수요 검증 데이터 없음.** Phase 3 전에 반드시 확인 |

## 6. 이 프로젝트에서 아직 검증되지 않은 것 (정직하게)

문서 전체가 잘 짜여 있다고 해서 이것이 검증된 사업이라는 뜻은 아니다. 현 시점에서 **확인된 것은 API 단가뿐**이다.

**모르는 것:**
- 국내에 이 형태의 제품에 돈을 낼 회사가 얼마나 있는지 — 조사한 바 없음
- 경쟁 제품이 이미 어떤 가격에 팔리고 있는지 — 확인한 바 없음
- 번역 품질이 실제 비즈니스 회의에서 쓸 만한지 — Phase 1에서 측정 예정
- 우리가 잡은 지연 목표가 실제 대화에서 충분한지 — 측정 예정

**Phase 1의 진짜 목적은 코드를 만드는 것이 아니라 위 항목 중 3·4번에 답하는 것이다.** 답이 부정적이면 Phase 2로 넘어가지 않는 것이 올바른 결정이다.
